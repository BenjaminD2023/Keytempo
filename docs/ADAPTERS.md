# 输入用途适配器

基础全局路径与实际实现的 `ConfirmedTextView` 都输出 `TypingCore.ClassifiedInput`，统计核心不依赖 AppKit、AX 或输入文本。真实实现位于 `Sources/Keytempo/ConfirmedEditor.swift`，可以运行 Keytempo 的“验证输入”页和 `--self-test-editor` 检查；这不是只有协议而没有实现的接口。

## 一次物理操作

实际适配器以 `keyDown` 建立瞬时操作作用域，再依据该作用域中的 `insertText`、`setMarkedText`、编辑命令或实际 marked-text 状态确定用途。每个操作至多发一条有效敲键摘要，携带单调时间、当次墙钟日期、唯一上下文版本、类别、证据、来源、输入源语言和可选操作 ID。多次提交回调不能伪装成多次手动敲键。编辑器重建使用进程内唯一操作 ID 和上下文；焦点离开、鼠标导航、命令、粘贴、自动补全、重复键中断段落。

已知 Command/Control 组合与已处理的原生 key equivalent 属命令，即使某个命令内部调用 `insertText`，也不能计作手动文字。Shift 大写与 Option 特殊字符仍允许走正常输入路径。全局按键元数据不能保证识别任意应用自定义快捷操作，不能将内置编辑器的支持范围推广到所有应用；证据不足的活动保留 unknown。

`confirmed` 说明适配器提供了实际操作证据，不是对人的意图或“没有任何宏”的保证。系统事件或第三方 IME 可能由自动化产生；来源检测不完整，不能做防作弊宣称。

## 文字提交数量

已接入的 `insertText` 提交负载只在回调中短暂用于扩展字素簇数量，以及兼容的 ASCII 标量与 Han 标量计数，然后丢弃。外部只收到数量、语言和覆盖元数据。拼音组合不记作上屏字符，选词动作不额外增加字符，取消／仅 unmark 不推断提交。已知粘贴、补全、重复键与无手动操作归属的插入不进入手动提交量。

`ClassifiedInput.committedCharacters` 区分 `nil` 与 `0`：`nil` 表示没有可靠提交覆盖，不能充作“已观察到零字符”；`0` 表示操作路径已覆盖，但此次组合或编辑没有提交。文字批量上屏时记录整批字素簇数，不把一次提交强行当一个字符或一串物理敲键。`probable` 数据即使传来字符数量，核心也不会将其用作 confirmed 字符覆盖。

字符 CPM 只接受两端均 confirmed、同语言、均有提交覆盖证据的连续间隔。分子为末端操作整批提交的字符数量，分母为该间隔的完整真实秒数；编辑或组合的零字符间隔保留其耗时。段首提交只进入字符总量，不产生没有前置可测时间的速率。默认累计至少 4 个覆盖间隔、0.5 秒并有正字符产出才展示。没有新事件时不追加尾部时长，字符速率与敲键节奏都冻结。跨午夜按实际时间比例分配速率的 `ratedCharacters`、覆盖秒数及间隔权重，实际字符总量仍归最终提交日。

菜单栏的主要单位依据输入源语言选择：`zh/ja/ko/th/lo/km/my` 使用真实字符 CPM，其他已识别语言使用“按键折算 WPM（估算）”＝输入过程 KPM ÷ 5。后者包含已接受的组合与编辑，不使用批量提交字符计算，也不代表实际词数。未知语言不强制选单位。全局监听缺乏真实提交边界，字符语言在全局模式显示 CPM 不可用；当前可验证的 confirmed 字符路径仅限 Keytempo 验证输入区。

要接入 Rime 或 InputMethodKit，应在实际组合、候选动作、英文直通、特殊提交与最终提交边界分别提供证据，不能用某个组合更新回调代替所有提交路径。已知手动组合的异步提交若无法归属到可测输入间隔，只进入未定速率的字符总量并中断段落，不进入 CPM 分子或伪造一串物理敲键。失去手动归属的异步插入不计入手动字符。不得通过轮询完整输入框或屏幕补齐数据。

## 输入源语言与汇总

`InputLanguages` 缓存 TIS 输入源声明的首要语言，经 `InputLanguagePolicy` 归一成主要语言代码；不对提交内容进行语言或语义识别。中文输入法中英文直通仍归中文源。默认全部语言可统计，显式空选择表示全部停止，`und` 可独立选择。语言筛选同时约束全局与已接入适配器，排除时不留下可连接到后续事件的旧段落；输入源与策略变化使组合归属失效。

schema v2 按日期、时区、规则、证据与语言保存汇总，字符总量和 CPM 覆盖字段独立。旧记录迁移为 `und`，不根据旧 ASCII／Han 数量反推语言或伪造字符速率。历史图表只绘制一种语言的主要单位，WPM 与 CPM 不混合；CSV 分别保留辅助 KPM、`estimated_wpm` 和有充分覆盖时的 `character_cpm`。

## 去重和中断

同一来源内部必须避免重复发送；多来源共同覆盖一个操作时，必须共享唯一 `operationID`。核心保存最近 256 个 ID，先去重再处理中断，采用首条报告，不对已经记账的 probable 自动升级证据。没有共享身份就不应同时声称完整去重。接入 confirmed 适配器时应先将其拥有的上下文从全局估算路径排除，避免全局先到的 probable 抢先归属。当前全局 tap 排除本应用，避免内置编辑器与全局重复计数。更换来源、证据或上下文始终切段。应用排除设置也会同时禁用本应用的验证适配器计数。

外部适配器必须在焦点失效、权限丢失、组合归属未知、睡眠和来源中断时立即使上下文无效。任何暂存都有上限，确认后只能按原始时间回溯；不能把等待确认的时长计入输入段。
